# Сервис учёта личных расходов

Курсовая работа по SQL. Веб-приложение помогает записывать повседневные расходы и смотреть, на что ушли деньги за выбранный период. Для каждой траты сохраняются сумма в рублях, дата, категория и комментарий.

## Возможности

- Создание и переименование категорий. Пустые категории можно удалять.
- Добавление, редактирование и удаление расходов.
- Просмотр истории за неделю, месяц, 6 месяцев, год, за всё время или за период, заданный вручную.
- Фильтрация расходов по категории.
- Формирование отчёта с общей суммой расходов и суммами по категориям.

У истории и отчёта свои настройки. Например, можно открыть историю покупок за неделю, а отчёт сформировать за месяц. Готовый отчёт обновляется по кнопке **«Сформировать отчёт»**. Историю и отчёт можно скрыть по отдельности.

## Запуск через Docker Compose

1. **Установите Docker и запустите его.**

   - **Windows и macOS:** установите Docker Desktop 

2. **Скачайте проект.** На странице репозитория нажмите **Code → Download ZIP** и распакуйте архив.

3. **Откройте терминал в папке проекта.**

4. **Соберите и запустите приложение.** Выполните команду:

   ```bash
   docker compose up --build -d
   ```

5. **Откройте приложение.** В Docker Desktop перейдите в раздел **Containers** и раскройте проект **expenses**. В строке **frontend** нажмите **8080:80**. В браузере откроется страница «Учёт личных расходов».

      Если вы используете Docker Engine без Docker Desktop, откройте браузер на том же компьютере и введите `localhost:8080` в адресную строку.

### Адреса после запуска

| Что открыть | Адрес |
| --- | --- |
| Страница учёта расходов | `http://localhost:8080` |
| Документация основного API — категории и расходы | `http://localhost:8000/docs` |
| Документация API отчётов | `http://localhost:8001/docs` |

Адреса `localhost` работают на том компьютере, где запущен проект. В документации Swagger можно посмотреть доступные запросы, их параметры и ответы сервисов.

### Остановка и повторный запуск

Чтобы остановить приложение, выполните в папке проекта:

```bash
docker compose down
```

Расходы и категории сохраняются в томе Docker. Для повторного запуска выполните:

```bash
docker compose up -d
```

## Как устроен проект

| Часть проекта | Назначение |
| --- | --- |
| `frontend` | Веб-страница. HTML задаёт поля и кнопки, CSS отвечает за оформление, JavaScript отправляет запросы и показывает результаты. |
| `main_service` | Основной сервис на Python и FastAPI. Проверяет данные и выполняет операции с категориями и расходами в SQLite. |
| `reports_service` | Сервис отчётов на Python и FastAPI. Получает расходы у основного сервиса по HTTP в формате JSON и рассчитывает итоги. |
| `docker-compose.yml` | Запускает веб-страницу и оба сервиса в трёх отдельных контейнерах. Подключает том для хранения базы данных. |

В базе SQLite две таблицы. В таблице `categories` хранятся номер и название категории. В таблице `expenses` каждая трата связана с одной категорией через поле `category_id`. Поэтому при переименовании категории её новое название появляется и у ранее добавленных расходов. Все суммы учитываются в рублях.

## Диагностические сообщения

### Категории

| Сообщение | Почему появляется | Что сделать |
| --- | --- | --- |
| `Сначала создайте категорию` | В базе пока нет категорий. Подсказка видна в форме расхода. | Введите название в разделе «Категории» и нажмите «Добавить». |
| `Введите название категории` | При добавлении категории поле оставлено пустым или содержит только пробелы. | Введите название, например «Учёба». |
| `Введите название от 1 до 50 символов` | При переименовании или отправке запроса в API указано пустое или слишком длинное название. | Введите название длиной от 1 до 50 символов. |
| `Категория с таким именем уже существует` | Указанное название уже занято другой категорией. | Выберите существующую категорию или введите другое название. |
| `Категория не найдена` | Запрос ссылается на категорию, которой нет в базе. | Обновите страницу и выберите категорию из актуального списка. |
| `Нельзя удалить категорию, у которой есть расходы` | К категории привязана хотя бы одна трата. | Чтобы сохранить траты и удалить категорию, сначала перенесите эти записи в другую категорию через кнопку «Изменить». |

### Добавление и редактирование расхода

| Сообщение | Почему появляется | Что сделать |
| --- | --- | --- |
| `Сумма должна быть больше 0` | В форме не указана сумма либо введён ноль или отрицательное число. | Введите положительную сумму. |
| `Введите сумму с точностью до копейки` | Введена сумма с долей копейки, например 250,505 ₽. | Укажите сумму с точностью до копейки, например 250,50 ₽. |
| `Укажите дату` | В форме расхода не выбрана дата. | Выберите день в поле «Дата». В истории он будет показан, например, как `25.11.2026`. |
| `Выберите категорию` | Для расхода не выбрана категория. | Выберите категорию из списка. Если список пуст, сначала создайте категорию. |
| `Расход не найден` | Запись, которую пытаются изменить или удалить, отсутствует в базе. | Нажмите «Показать историю» и выберите запись из обновлённого списка. |

### История и отчёт

| Сообщение или результат | Почему появляется | Что сделать |
| --- | --- | --- |
| `Дата начала позже даты окончания` | В поле «С» выбран день позднее даты в поле «По». | Исправьте границы периода. Чтобы посмотреть один день, укажите одинаковые даты. |
| `По выбранным условиям расходов нет` | В истории нет записей за выбранный период и категорию. | Расширьте период или выберите категорию «Все» и снова нажмите «Показать историю». |
| В отчёте показано `0,00 ₽`, список категорий пуст | За выбранный период и категорию не найдено расходов. | Проверьте фильтры самого отчёта и нажмите «Сформировать отчёт». |

### Проверка данных через API

В истории расходов и в готовом отчёте даты отображаются в формате **ДД.ММ.ГГГГ**. На странице день можно выбрать в календаре. При ручном запросе через Swagger та же дата передаётся в формате `2026-11-25`.

| Сообщение | Почему появляется | Что сделать |
| --- | --- | --- |
| `Введите положительную сумму в рублях, не более двух знаков после запятой и до 12 цифр до запятой` | Основной сервис получил недопустимое значение поля `amount`. | Укажите положительную сумму в допустимых пределах. В JSON пример записи — `"amount": 250.50`. |
| `Комментарий — не более 200 символов` | В API передан комментарий длиннее 200 символов. В форме на странице уже установлено ограничение длины. | Сократите комментарий или оставьте его пустым. |
| `Укажите дату расхода` | При создании записи пропущена дата либо сервис не смог прочитать переданное значение. | В форме выберите дату в календаре. При ручном запросе проверьте поле `date`. |
| `Укажите номер категории` | В запросе отсутствует обязательное поле `category_id` или его значение не распознано как целое число. | Укажите номер существующей категории. Номера можно посмотреть запросом `GET /categories`. |
| `Проверьте дату начала периода` | Основной сервис не смог прочитать значение `from_date`. | Проверьте начальную дату. Если нужна выборка без ограничения по началу периода, пропустите этот параметр. |
| `Проверьте дату окончания периода` | Основной сервис не смог прочитать значение `to_date`. | Проверьте конечную дату. Если нужна выборка без ограничения по концу периода, пропустите этот параметр. |
| `Проверьте параметры запроса` | Основной сервис обнаружил ошибку в запросе, для которой нет отдельной подсказки. | Сверьте параметры и содержимое запроса с описанием в Swagger. |
| `Проверьте введённые данные` | Сервис вернул ошибку без текстового пояснения, которое страница могла бы показать. | Проверьте поля. При работе через Swagger посмотрите подробности в ответе на запрос. |

### Подключение к сервисам

| Сообщение или признак | Почему появляется | Что сделать |
| --- | --- | --- |
| `Не удалось связаться с сервисом` | Браузеру не удалось получить ответ от основного сервиса или сервиса отчётов. | В папке проекта выполните `docker compose ps`. Если приложение остановлено, запустите его командой `docker compose up -d`. |
| `Не удалось связаться с основным сервисом: …` (HTTP 503) | Сервис отчётов не смог связаться с основным сервисом. После двоеточия указана техническая причина. | Проверьте состояние контейнеров командой `docker compose ps`. Сообщения основного сервиса доступны по команде `docker compose logs main_service`. |
| `Основной сервис вернул ошибку: …` (HTTP 502) | При формировании отчёта основной сервис ответил ошибкой. После двоеточия указан код его ответа. | Выполните `GET /expenses` с теми же параметрами в документации основного API и проверьте ответ. |
| `{"detail":"Not Found"}` (HTTP 404) | Открыт адрес, для которого у сервиса нет страницы. Например, это происходит при переходе на `localhost:8000` или `localhost:8001` без `/docs`. | Для работы с расходами откройте `localhost:8080`. Документация основного сервиса доступна по адресу `localhost:8000/docs`, документация сервиса отчётов — `localhost:8001/docs`. |

### Подтверждения действий

| Сообщение | Что означает |
| --- | --- |
| `Новое название категории` | Открылось окно переименования. Введите новое название или нажмите «Отмена». |
| `Удалить категорию?` / `Удалить расход?` | Приложение ожидает подтверждения удаления. |
| `Категория добавлена` / `Категория переименована` / `Категория удалена` | Действие с категорией успешно выполнено. |
| `Расход добавлен` / `Расход обновлён` / `Расход удалён` | Изменения сохранены. Чтобы увидеть новый итог в уже открытом отчёте, нажмите «Сформировать отчёт». |
